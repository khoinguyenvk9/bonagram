# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`bonagram` is a terminal Telegram client in Go: [gotd/td](https://github.com/gotd/td) (MTProto) + Bubble Tea v1. User-facing docs (keys, config, requirements, limits) are in `README.md` (English) and `README.vi.md` (Vietnamese); keep both in sync when behaviour changes. The UI text is Vietnamese. The look is a fixed dark theme (colour constants at the top of `view.go`) that follows the design canvas the user approved (https://claude.ai/artifact/SiKB5jvEMEqpagtkoaDeoo): graphite, one amber accent, no borders except the message box.

## Commands

```bash
go build -ldflags="-s -w" -o bonagram .   # the binary the user runs (./bonagram); needs Go >= 1.26 (the go.mod minimum comes from the dependencies)
go vet ./... && go test -race ./...       # all tests; none touch the network
go test -run TestModelFlow ./...          # one test
```

There is no linter config beyond `gofmt`/`go vet`. Tests use fake data only: `bonagram_test.go` drives the Bubble Tea model by sending messages to `Update` and checking `View()`; it never connects to Telegram. Anything that calls the API (`loadChats`, `loadMessages`, sending, marking read) is only verifiable by running the app against a real account.

First run asks for `api_id`/`api_hash`, then the phone/code login on plain stdin. Config and session live in `~/.config/bonagram/` (`env`, `session.json` = full account access, `width`).

## Architecture

Single `package main`; the pieces that must be read together:

- **`main.go`**: wiring. `gotd` client → `updates.Manager` (`gaps`) → `tg.UpdateDispatcher` → handlers push `newMsg`/`reactMsg` into a buffered `events` channel. The model drains that channel with the `wait()` command, which **must be re-armed by every handler of an event from the channel** (`onNew`, `onReact`), otherwise live updates silently stop. The Bubble Tea program runs in a goroutine; `gaps.Run` blocks the main one; quitting the UI cancels the shared context.
- **`tg.go`**: data types (`chat`, `line`, `topic`, `reaction`) and everything that talks to the API (`loadChats`, `loadMessages`, `loadTopics`, `markRead`, `sendText`). All text from Telegram goes through `clean()` (strips control, private-use, format and variation characters) so it cannot inject escape sequences or break width calculations.
- **`ui.go`**: the Bubble Tea `model`: state, `Update`, key/mouse handling, commands that return `...Msg` results. Value-receiver `Update`/`View`, but mutations happen through pointer methods on the local copy (`m.update`). Messages are cached per view in `m.msgs`, keyed by chat key, or `chat#topic` in forums (`mkFor`).
- **`view.go`**: pure rendering. The whole frame is built line by line and every line goes through `paint()` (re-applies colours after each reset and pads to the exact width). The frame must be exactly `h` lines of `w` cells; tests assert this. `render()` also records `lineAt` (first content line of each message) and `hits` (copy buttons), which mouse handling reads.
- **`code.go`**: code blocks and the copy button (entity offsets are UTF-16 units, hence `segments`), clipboard via OSC 52 + `pbcopy`/`wl-copy`/`xclip`.
- **`media.go`**: downloads, image drawing (Kitty unicode placeholders, or half-blocks fallback; `BONAGRAM_IMAGES` forces one), and `lockedOut`/`termWrite`.
- **`input.go`**: filter that repairs mouse reports Bubble Tea split in two (they would otherwise be typed into the input box).

README screenshots: `scripts/shots.sh` (fake data in `screenshot_test.go` → HTML → headless Chrome → ImageMagick); re-run it when the look changes. `demoModel` is the main picture (folders, typing, ✓✓); `shotScenes` draws the others (message menu, who reacted, chat › Thư mục, upload progress, folded rail + private chat), each from a fresh `demoModel`; look at the PNGs before committing (a scene that opens the wrong chat still "passes").

## Non-obvious things

- **All terminal output goes through one mutex** (`lockedOut` is Bubble Tea's output; image/bell/OSC writes use `termWrite`). Each Bubble Tea frame is wrapped in autowrap-off (`?7l`…`?7h`) and followed by a move of the **real** cursor to the focused input, because IME composing text (Vietnamese Telex/VNI) is drawn at the real cursor. The built-in virtual cursor of the text inputs is disabled for that reason. A cursor move that leaves the frame unchanged (←, Home, click) makes Bubble Tea skip the frame, so `setCursor` writes the move itself once drawing started (`drawing`); without it the Telex word being composed appeared at the old cursor spot. `lockedOut` must keep `Read/Fd/Close`, or Bubble Tea stops recognising the terminal and the screen stays blank.
- **Widths**: use `ansi.StringWidth`/`ansi.Truncate` (grapheme-aware), never `runewidth`, for anything that is laid out; mixing the two shifted rows and overlapped chats.
- **gotd quirks**: `FolderID(0)` means "unset", so `GetDialogs` returns archived chats too; filter on `Dialog.FolderID != 0`. The updates manager only follows channels it was told about, so `loadChats` returns `chanTrack`s that are registered with `TrackChannel` (otherwise group messages arrive late or not at all). The manager runs on in-memory state only.
- **Forum unread**: the server keeps a per-forum unread count that is not lowered when a topic is read (seen stuck at 7 while every topic said 0), so the badge of a forum is the sum of its topics' counts (`sumUnread`); `loadChats` fetches the topics of every forum for that, and `open` refetches them. Reading a topic is `messages.readDiscussion(peer, topic id, up to message id)` (verified accepted by the server).
- **Message actions** (`actions.go` = requests, `msgactions.go` = keys and results): edit/delete/react/forward/open link/jump to mention are keys of browse mode (`^B`); files are sent from `attach.go`: `/file a b` or the `[Tệp]` button/`Ctrl+O` (system dialog: osascript / PowerShell / zenity|kdialog) only *stage* paths in `m.attach` (shown by `barText()`), the next Enter sends them with the input as caption (`sendFiles`: photos/files grouped into albums of ≤10, `groups`; `sendAttached` refuses files over `fileMax` (2000 MB, 4000 with `cfg.premium` from `Self`) before uploading, and shows its progress as an `xfer` (`transfer.go`, see Transfers below)). `video.go`: mp4/mov/m4v go as video documents (`videoOpt`: `probeVideo` reads mvhd/tkhd boxes itself for duration, size (swapped when rotated 90°) and moov-before-mdat = `SupportsStreaming`; cover by `ffmpeg` if installed (`videoThumb`, ≤320 px, uploaded without progress); unreadable ones stay files); photos and videos share albums, `upload.media()`); the pinned messages are one `messages.search(filter=pinned, limit 20)` per `enter` (`m.pins` per view, newest first; a click on the pinned row runs `jumpPin`, which advances `m.pinAt` and calls `jumpTo`: select the message if loaded, else `loadAround` with `aroundMsg.jump`; reply quotes use `jumpTo` too, through `m.quoteAt` rows recorded by `render` and checked in `clickMessage`; a jump whose message is gone toasts); drafts are kept per `chat#topic` in `m.drafts`. The row above the input is `barText()` (prompt, edit, or reply) and `msgY()` counts the pinned row: both feed `layout()`, so call `layout()` after changing them. Gotchas found against the real account: (1) results of our own sends/uploads/forwards are **not** announced back as updates, so `sendText` returns the id from the reply (`sentID`, `numberSent`) to make a just-sent line editable, and uploads/forwards refetch the open chat (`refresh`); (2) in Saved Messages the server does not mark messages `out`, hence `mine()` uses `selfKey`; (3) delete only own messages, never others' (`Revoke` would remove them for the other person too); (4) forwards go only where the user picks, and live tests of write actions belong in Saved Messages only (the user said: never forward to anyone else).
- **@mention suggestions** (`mention.go`): typing `@` at the start of a word in a group asks the server for members after a 150 ms pause (supergroups: `channels.getParticipants` with a search filter; basic groups: `messages.getFullChat` once, cached in `m.members`, filtered locally). Nothing is loaded ahead of time. The choices are one row in `barText()`. A member without a username is inserted as `@Name` and sent as an `InputMessageEntityMentionName` (`m.pend`, `mentionEnts`); one with a username is plain text. Not offered in private chats.
- **Reading messages**: a reply is shown as `│ name  text` (bar and name in the author's colour) for every reply (`render` looks the target up in the loaded lines; older targets are fetched once per page by `fillQuotes` into `line.quote`; otherwise "trả lời một tin nhắn cũ"). Hidden links (`MessageEntityTextURL`) are written after their words by `showLinks` (not in messages with code blocks); `L` copies `linksOf`. A live message whose sender is missing from the update entities (`from == "?"`) takes a name seen earlier in a loaded line (`nameOf`) or re-reads the chat; it must never fall back to the group title (that is only right for anonymous admins). Links are drawn by `linkedText` as OSC 8 hyperlinks (`id=` ties the rows of a wrapped link; `relink` closes/reopens them per row because `ansi.Wrap` does not) in the link colour; `linkSpans` reads their screen positions back out of the drawn rows into `m.links`, which drives hover (`hoverAt`: the program uses `WithMouseAllMotion`, View costs ~0.10 ms so motion events are cheap; `m.hover` is the address underlined by the next `render`) and click (`endSel`: a press and release on the same link without a drag opens it through `openURL`). Terminals cannot report Cmd, so plain click is the in-app trigger; Cmd+click is the terminal's own OSC 8 handling (support list in README, double-open risk unverified). Mouse text selection is `select.go`: `render` keeps the drawn rows in `m.rows`/`m.rowOut`, press/drag/release over the message view marks cells (reverse video via `paintContent`) and release copies them; the terminal's own selection is not available because the app owns the mouse.
- **Formatting and search**: `format.go` parses the input as Telegram markdown (`**` `__` `~~` `||` backticks, `[t](url)`; single `*`/`_` are not marks) into text + entities on send and edit (`parseMarkdown`; mentions are computed on the stripped text) and writes them back for editing (`toMarkdown`, round-trip tested). A line we just sent carries a synthetic `msg` (ID 0) so it is drawn formatted at once; `addLine` lets the server's copy replace it. All text drawing goes through `inline` (entities → SGR + OSC 8, `carry` makes wrapped rows self-contained). `msearch.go`: Ctrl+F uses the input as the query, `messages.search` (50, no paging), results replace the message view, Enter loads the window around the hit (`loadAround`: getHistory/getReplies with a negative add_offset) and marks the chat `detached`: live messages are not appended and Esc reloads the latest; leaving the chat drops the old stretch. Deletions by others are deliberately NOT followed (the user likes seeing what was sent and deleted).
- **Files**: in the message view a document is a card (`card.go`: badge coloured by extension, name, size; rows of equal width, drawn without the own-message colour), everywhere else (`mediaTag`/`docTag`, chat list, copy) a one-line label. Media labels with names, sizes and durations (`[file] a.pdf · 2.3 MB`; link previews add nothing). Enter on a file → `mediaCmd`: `downloadDoc` saves into `~/Downloads` (`savePath`: same name+size reused, else `name (1).ext`), checks the size, retries once with a fresh file reference when `FILE_REFERENCE_EXPIRED` (reads the message again), opens known-harmless extensions (`openable`) via `openURL`, otherwise `revealFile` (never runs it). The result is a `doneMsg`: errors go to `m.err` (stay) and progress is `m.note`; a click on a file only selects (files can be big). gotd's main client already follows FILE_MIGRATE, so other-DC files need no special handling. The real cause of the user's "cannot download" report was not reproduced (no live test was allowed): suspects were the hidden cache folder, the 6 s toast, and expired file references.
- **Images, video, stickers, locations**: `images.go` picks the viewer protocol (`rawProto` = iterm|sixel from env, `kitty` separately; tmux → none). iTerm2/Sixel pictures are blank rows plus `picture.raw`, painted once right after the next frame by `lockedOut.Write` (`queueDraw`/`takeDraw`, `drawnID`; a resize resets it, closing the viewer sends `tea.ClearScreen`). The list (thumbs, stickers) only ever uses Kitty placeholders or half-blocks. Sixel is our own encoder (Plan 9 palette + Floyd–Steinberg). Pictures sent as files (`imageDocOf`: `image/*` document, not sticker/GIF, with `Thumbs`) get a preview from the document thumbnail (`downloadDocThumb`, size via `pickOf`), drawn under their file card; Enter still downloads the original. Static webp stickers are fetched into the cache by `stickerCmds` (newest 12) and drawn as thumbs. Videos/GIFs play through `mpv` with `tea.ExecProcess` (`mpvArgs` picks kitty/sixel/tct) when installed, else the system player. `location.go`: `geoCard` (OSC 8 Google Maps link, also in `linksOf`), `/position` (`parsePosition`, `sendGeo` → refresh).
- **Pinned chats** (`chat.pinned`, from `Dialog.Pinned`) are sorted first at load and `placed()` keeps them above activity: a new message lifts a chat only to the top of the unpinned ones, a pinned chat stays in its slot. Pin changes made while the app runs are not followed.
- **CLI and help** (`help.go`): `cli()` handles `--version/--help` before anything starts (unknown option: exit 2); `version` is set with `-ldflags "-X main.version=..."`. The in-app guide is `m.help` (F1; scrolls with arrows/wheel), its text is `helpDoc`: update it whenever keys change. The first launch opens it once (marker file `help-seen` in the config dir). Keep guide rows short (about 56 characters): longer ones are cut in an 80-column window.
- **Reads happen on open**: opening a chat with unread messages marks it read on the server. When trying the app against a real account, pick chats without unread messages, and do not message other people; Saved Messages ("me") is the safe place for live tests (delete the test message afterwards).
- The renderer frame rate is `BONAGRAM_FPS` (default 60). It was tried at 30 (idle CPU 0.67% -> 0.41%) but the user found typing/scrolling slightly slower, so 60 stays the default; do not lower it without asking. `GOMAXPROCS` made no difference to CPU.
- Shutdown: SIGHUP/SIGTERM are handled like Ctrl+C, and from the moment quitting starts (QuitMsg or context cancelled) a 3 s `os.Exit` timer guards against a wedged exit (a leftover process was seen twice after Ctrl+Q + closing the terminal, cause not found, not reproducible in ~10 tries; with v0.2.1 none in 20 Ctrl+Q runs and 10 Ctrl+Q + close runs). Always check for leftover `bonagram` processes after testing in tmux.
- Edit updates (`OnEditMessage`/`OnEditChannelMessage` → `editMsg` → `onEdit`) are what makes a bot's streamed answer (one message edited many times) show in full; like reactions they redraw at most every 250 ms and `onEdit` must re-arm `wait()`. Deletions by others are still not handled.
- **Reads on other devices**: the three read-inbox updates → `readInMsg` → `onReadIn` (re-arms `wait()`). Users/basic groups/channels take `StillUnreadCount`; forums ignore the forum-wide update and refetch their topics with a `quiet` `topicsMsg` (counts only, no `enter`, so the open view does not jump).
- **Transfers** (`transfer.go`): sends (`sendAttached`) and file downloads (`mediaCmd` on a document; photos are small and stay a plain note) are `xfer`s in `m.xfers`, started by `startXfer` (its context is what `Ctrl+X` → `cancelXfer` cancels, newest running first). Progress comes from the uploader's `Chunk` (summed per upload ID) or the downloader's `WithProgress` (`got`); `xferTick` (400 ms) writes the newest one into `m.note` and forgets finished ones; the answers (`actMsg.up`, `doneMsg.x`) call `endXfer`. A cancelled download returns "Đã huỷ tải" and `fetchP` removes the `.part`. Do not pass the size to gotd's downloader (`WithSize`): with it a download the server cut short came out padded and passed the size check.
- **Typing and online** (`typing.go`): the three typing updates → `typingFrom` → `typingMsg` (pushed with `pushLossy`: dropped when the queue is full, like `statusMsg`) → `onTyping` (re-arms `wait()`); `m.typing` per chat, entries last `typingFor` (6 s) and a 1 s `typingTick` runs only while any are left; a new message from the typer ends it (`typingDone`). Shown by `typingText` in the list row (View sets the transient `chat.typing`) and in the title row (forum: open topic only). Names come from the update's users, else `nameOf`. Our own typing: `typedCmd` after a key that changed the editor (`ver`), at most every `typingEvery`, not in Saved Messages, channels (`chat.broadcast`), commands or edits. Online status: `chat.seen` (`presence` from `User.Status` in `loadChats` via `kindOf`, live `updateUserStatus` → `statusMsg`), shown by `chatSubtitle(c, now)` via `presenceText`. Not tried against a real account.
- **Folders** (`folders.go`): `messages.getDialogFilters` at start (`Init`) and again on the three dialog-filter updates (`foldersChanged`); `toFolders` returns nil when the user made none (no tabs). `folder.has`: named chats are always in/out, else by kind (`chat.bot`/`contact`/`broadcast` from `kindOf`) then exclude muted/read. The tabs take the blank row above the list (`listY0-1`, so nothing moves), clicked through `clickFolder`, `Ctrl+L` cycles; the row scrolls sideways from `m.tabOff` (`drawTabs` draws `‹`/`›` as spans `tabLeft`/`tabRight` when tabs are hidden; a click on them or the wheel over the row → `scrollTabs`, which stops at the last tab), and `fitTabs` (on a folder change, new folders, or a new list width via `m.tabW` in `Update`) scrolls the shown folder into view and pulls hidden tabs back in when there is room; `visible()` filters only when the search is empty. The tab row is memoised (`tabMemo`, signature `tabSig` over chats + folders `gen` + width) because counting each folder's unread chats per frame cost ~0.1 ms at 1,000 chats × 8 folders (`BenchmarkViewFolders`). Adding/removing a chat: right-click › Thư mục (`folderItems`, ✓ = `has`) → `withChat` builds a changed copy of the server's `folder.raw` (never mutating its slices: add = un-exclude + include unless already included/pinned; remove = drop from include/pinned, and exclude when the folder takes it by kind, `kindIn`) → `saveFolder` (`messages.updateDialogFilter`, Vietnamese messages for FILTER_INCLUDE_EMPTY / *_TOO_MUCH) → `actMsg{kind: "folder"}` → `onFolderSaved` swaps the folder in. Shared folders (`DialogFilterChatlist`, `shared`) only toast. Creating/renaming/deleting folders is not done. Folder-pinned order is not used (the list keeps its own order). Not tried against a real account.
- **List read marks**: `chat.lastID`/`lastOut` (from the dialog's last message, `onNew`, our own send with `lastID` 0 until `numberSent`) draw ✓/✓✓ before the time in `chatItem` against `chat.readOut`; none in Saved Messages or channel posts.
- **Read marks and people search**: `chat.readOut`/`topic.readOut` come from `Dialog.ReadOutboxMaxID`/`ForumTopic.ReadOutboxMaxID` and move forward on the three read-outbox updates (`readOutMsg` → `onReadOut`, which must re-arm `wait()`); `ticks` marks a run of own messages ✓✓ only when all of it is read (none in Saved Messages or channel posts). In `Ctrl+K`, from 3 letters `contacts.search` runs after a 400 ms pause; results not in the list live in `m.found` and appear in `visible()` as indexes past `len(m.chats)`: read them with `chatAt`, and `open`/`forwardTo` turn them into list chats with `pick`. Neither was tried against a real account yet.
- **Message box** (`editor.go`): our own multi-line editor, not bubbles' textinput/textarea (textarea hides where its cursor is drawn, and the real cursor must sit there for IME). It keeps textinput's method names so callers did not change; `View()` returns the rows shown (1..`editorRows`), `Cursor()` the cursor cell for `setCursor`, `Height()` feeds `layout()`. `model.Update` re-runs `layout()` whenever the height changed, so code that sets the value need not. Enter stays with the app (send); `Alt+Enter`/`Ctrl+J` insert a newline (Bubble Tea v1 cannot see Shift+Enter). Pastes keep newlines; tabs become 4 spaces. ←/→/Backspace/Delete step by grapheme (`prevG`/`nextG`, uniseg): "á" pasted as a + U+0301 or a ZWJ emoji is one step. `SetValue` clears undo. Emoji suggestions (`emoji.go`) are a second bar like @mentions (`m.ec`, `emojiCheck` after each input key/click).
- **Right-click menu** (`menu.go`, the user's pick "C" from the design canvas): a right press over the message view selects the message (browse mode) and opens `m.menu`; a message menu has a reaction row on top (`ctxMenu.reacts`, `sel == -1` with `rsel` = emoji; click, Enter or digits 1–7 → `menuReact` → `answerPrompt`), then items that reuse the browse-mode code (`actionKey`, `copyFrom`, `mediaCmd`, `answerPrompt` for delete). Sub-menus (`subMenu`) replace the items in place and show a title row. Rows: `head()` (blank + title/reactions + line) then items then a blank; `menuHit` maps cells back. No border, `cBoost` background; `icon` is a Nerd Font glyph (1 cell) left out when `cfg.icons` is false (`BONAGRAM_ICONS=off`). An item without `run` is a separator; `hint` is the browse key on the right, `danger` draws it red. While open it takes every key and mouse event (`menuKey`/`menuMouse`); `View` draws it last over the finished rows (`overlayMenu`, cut with `ansi.Truncate`/`TruncateLeft`). iTerm2/Sixel pictures painted after the frame can cover it.
- **Pin chat** (`pinChat`, `messages.toggleDialogPin`; `repin` puts a newly pinned chat first, an unpinned one back among the others by date; PINNED_DIALOGS_TOO_MUCH becomes a Vietnamese message). Pin changes made on other devices are still not followed.
- **Pin, mute, delete chat** (`pinItem`, `openChatMenu` in `menu.go`; `pinMessage`, `setMuted`, `deleteChat` in `actions.go`; results are `actMsg` kinds pin/mute/delchat). Pin: groups notify/silent, private chats both/only me (`PmOneside`); "Bỏ ghim" when the id is in `m.pins`; success refetches the pinned row. Mute is forever (`MaxInt32`) or off, and only `chat.muted` changes locally (changes made elsewhere are not followed). Delete: private chats `messages.deleteHistory` in batches, revoke only when the user picks "Xoá cho cả hai bên" (an explicit, confirmed choice; the never-revoke rule for others' messages still holds everywhere else); supergroups/channels `channels.leaveChannel`; basic groups `deleteChatUser(self)` + best-effort history clear; Saved Messages is not offered. `dropChat` removes it from the list and cache.
- **Layout** (`view.go`): left `listHead` (blank, "Bonagram", unread count, a 3-row search field drawn with ▄/▀ half blocks, blank → `listY0` = 7), chat items of `itemRows`; right a 3-row header (blank, title · `chatSubtitle` with the toast or "Tìm ⌃F" at the end, blank), topic tabs, pinned band, messages, `barText`, `composeBox`, and the bottom row is `hints()` (mode-dependent key caps) under the right pane. `keyName`/`keyCap` spell keys per `runtime.GOOS`. In `render`, own messages are a `cOwn` block (`bubble` = widest row + 2, copy-button columns offset by it) with the time and `ticks` under the last of a run; `daySeparator` starts every day; quotes are `from\x00text` (`quoteText`) drawn by `quoteRow`. The attach/send buttons share `btnW`, right-aligned by `buttonLead`; `buttonWidths` splits their click areas. Ghostty draws a Nerd Font icon two cells wide when a space follows it, so every icon is followed by one spare space (menu rows, the paperclip, the send button) or it overlaps what comes next. File and location cards are one row (`cardRow`: badge, main text cut to fit, muted end, on `cBoost`). Narrow windows (`rail.go`): when the window has no room for the list at `sideWant` beside `minRight` columns of messages (`narrow()`), `fitSide` folds the list to `railW` (initials tiles of `itemRows` rows, so clicks, wheel and right-click map like the full list) unless `m.searching`; `model.Update` re-runs `fitSide` after every message, so opening or closing a search (or forwarding) unfolds/folds it without hooks. `m.sideWant` is the user's width (drag, saved); `m.side` is what is drawn. Dragging the divider more than `foldSnap` cells left of `sideMin` sets `m.folded` (rail in any window, saved as width `railW`); dragging back out clears it. A rail folded only by a narrow window does not drag: a short drag there once saved a fold the user never asked for, and the list then folded in wide windows after every chat was picked. Hovering a tile sets `m.railHot`, drawn by `railTip` with `overlayAt` (shared with the menu).
- **Performance rules** (measured with `bench_test.go`; compare against the last commit in a worktree before and after a change): in code that runs per frame or per message drawn, colour with `ink`/`inkB`/`chip` (cached escape sequences, `seq`) and `paint`, not `lipgloss` styles (a Render costs dozens of allocations; replacing them made a redraw 2.6× faster); cache anything drawn from message data (`quoteOf`/`quoteDrawn`, `cachedBody`); View takes the visible rows from `m.vlines` (set by `setContent`), never `m.vp.View()`; the editor's `rows()` is cached by `fix()` per (`ver`, `Width`).
- Reactions to own messages have their own unread state on the server (`chat.reacts` = `Dialog.UnreadReactionsCount`, `reactMsg.unread` from `RecentReactions[].Unread`); reading messages does not clear it, so `enter`/focus call `messages.readReactions` (`reactReadCmd`), else other devices keep the badge.
- **Who reacted** (`reactors.go`): message menu › "Ai đã thả react" (`reactorsItem`, offered when `canSeeReactors`: private chat, or `can_see_list` from the message or a live `reactMsg.canSee` → `line.seeWho`; never `chat.broadcast`). Private chats are worked out from `line.reacts` (`privateReactors`, no request); groups ask `messages.getMessageReactionsList` (limit `reactorsMax`) while a "Đang tải…" sub-menu waits (`ctxMenu.wait` = message id; a late `reactorsMsg` for a closed menu is dropped; FLOOD_WAIT is said in Vietnamese). `reactorsMenu` draws filter rows per emoji then people (as many as the window holds; the title counts the rest, total only when Telegram has another page); a person opens through `openPeer` (joins the list like a search result). Emoji go through `clean`, so ❤️ is ❤. Not tried against a real account.
- Reaction updates redraw at most every 250 ms (`renderTick`) and only when the message is in the open view; don't redraw per update.
